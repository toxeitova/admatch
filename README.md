# AdMatch — MVP

Сайт подбора Instagram/TikTok-блогеров для малого бизнеса в Алматы. Бизнес заполняет форму → сразу видит подборку проверенных блогеров → связывается «Через AdMatch» (комиссия 10% при сделке) или «Напрямую» (бесплатно).

MVP сделан под 14-дневный эксперимент:

- **E1** — свяжется ли бизнес с блогером из подборки (цель ≥ 4 из 8) → `v_e1`
- **E2** — доля «Через AdMatch» среди выборов способа связи (цель ≥ 40%) → `v_e2`

Стек: Next.js 15 (App Router, TypeScript) · Tailwind CSS 3 · Supabase Postgres (через REST/PostgREST) · Vercel · Telegram Bot API. Платных сервисов нет.

## База данных

Миграция: `supabase/migrations/0001_init.sql` — 6 таблиц (`creators`, `requests`, `matches`, `contact_requests`, `manual_requests`, `events`), CHECK-ограничения, индексы, триггер `updated_at`, RLS и 4 представления метрик. Миграция идемпотентна.

**Применить** (любой способ):

1. Supabase → SQL Editor → вставить содержимое файла → Run.
2. Или Supabase CLI: `supabase link --project-ref <ref>` → `supabase db push`.

**Безопасность.** RLS включён на всех таблицах, политик нет: ключ `anon` не видит ничего. Сайт читает и пишет только из серверных API-роутов и серверных страниц ключом `service_role`. Права на представления у `anon`/`authenticated` отозваны. Поле `creators.contact` не попадает ни в один ответ API, кроме ответа на выбор «Напрямую». Это обеспечивает белый список колонок в `lib/publicCreator.ts`.

### Управление данными

Админки нет — данные правятся в Supabase Table Editor:

- **creators** — блогеры. В подбор попадают только записи, где `active`, `consent` и `verified` равны true.
- **contact_requests** — заявки на связь. Команда двигает `status`: `new → checking → available/unavailable → intro_sent → deal/no_deal`; при сделке заполняет `deal_amount`.
- **manual_requests** — запросы ручного подбора.

### Метрики

```sql
select * from v_e1;              -- contacted_requests / total_requests (контакт в течение 14 дней после заявки)
select * from v_e2;              -- admatch_choices / total_choices / admatch_share_pct
select * from v_funnel;          -- уникальные сессии: wishes_submitted → results_viewed → card_opened → contact_clicked → deal_choice
select * from v_time_to_results; -- медиана seconds_from_landing

-- E2 в разрезе порядка карточек (проверка, не влияет ли позиция):
select props->>'order' as ord, props->>'choice' as choice, count(*)
from events where name = 'deal_choice' group by 1, 2 order by 1, 2;
```

## Тестовые данные и импорт

**Seed.** `npm run seed` загружает 15 вымышленных блогеров из `data/test-creators.ts` (`is_test=true`, handle `test_*`, цены 15 000–250 000 ₸, все 12 ниш). Даты публикации и проверки задаются относительно сегодняшнего дня, поэтому seed не «протухает» из-за фильтра «30 дней». Повторный запуск обновляет записи по `handle`.

Убрать тестовых блогеров из прода: `SHOW_TEST_DATA=false` (они перестают попадать в подбор) или `delete from creators where is_test;`.

**Импорт CSV.** Шаблон: `creators_template.csv`, колонки совпадают с полями `creators`.

```bash
npm run import -- creators.csv
```

- `niches` — через `;`, строго из справочника (`lib/niches.ts`): «Еда и рестораны;Лайфстайл».
- Булевы поля: `true/false` (также `1/0`, `да/нет`); пусто → значение по умолчанию.
- Даты: `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`.
- Числа можно писать с пробелами (`45 000`); `er_pct` — с точкой или запятой.
- `audience_gender`: `f`, `m` или `mixed`.
- Upsert по `handle`: существующие записи обновляются. Пустая ячейка обнуляет поле.
- Если хоть одна строка невалидна, ничего не загружается, а скрипт выводит номер строки и причину.

## Логика подбора

`lib/matching.ts` (чистые функции, покрыты тестами), веса — `lib/matching.config.ts`.

**Обязательные фильтры:** `active`, `consent` и `verified` = true · тот же город · ≥ 1 общая ниша · минимальная цена по выбранным форматам (или по всем непустым) ≤ `budget_max × 1.2` · последний пост не старше 30 дней или `null`. Тестовые записи участвуют только при `SHOW_TEST_DATA=true`.

**Баллы (макс. 100):**

| Критерий | Баллы |
| --- | --- |
| Ниша | 40 × совпавшие / ниши в заявке |
| Аудитория | +10 за пересечение возраста, +10 за пол (`all` или `mixed` — совпадение) |
| Бюджет | 20 — внутри [min, max]; 10 — ниже min или выше max не более чем на 20% |
| Алматы | round(10 × доля / 100) |
| Вовлечённость | 10 при ER ≥ 5; 5 при 2 ≤ ER < 5 |

Сортировка: score ↓ → доля Алматы ↓. В выдачу и в `matches` попадают топ-10.

**«Блогеры, которые вам нравятся».** Из текста поля извлекаются ники: `@nick`, `instagram.com/nick`, `tiktok.com/@nick` или просто `nick`. Сравниваются с `handle` и с ником в `instagram_url`/`tiktok_url`, без учёта регистра. Если такой блогер **проходит обязательные фильтры**, он ставится в начало подборки, а в «Почему подходит» первой строкой появляется «Вы отметили этого блогера». Балл «Подходит на N%» при этом не меняется. Блогер, не прошедший фильтры, в подборку не попадает.

«Что вы продвигаете?», «Требования к контенту», цель и сроки на подбор не влияют. Они нужны команде для ручной работы и приходят в Telegram.

«Почему подходит» — `why_fits_text`, а если он пуст, текст собирается из сработавших критериев: `Ниша: … · 72% аудитории из Алматы · Reels 45 000 ₸ — в вашем бюджете · Аудитория вашего возраста и пола · Вовлечённость 6,1%`.

## Telegram-бот

1. В Telegram откройте @BotFather → `/newbot` → получите токен → `TELEGRAM_BOT_TOKEN`.
2. Создайте группу команды и добавьте туда бота. Напишите в группу любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":-100…}`. Это значение для `TELEGRAM_CHAT_ID` (для групп оно отрицательное).
4. Чтобы бот видел сообщения в группе для `getUpdates`, временно отключите Privacy Mode: @BotFather → `/setprivacy` → Disable. Для отправки уведомлений это не требуется.

Уведомления (`lib/telegram.ts`): 🆕 новая заявка, 💰 сделка через AdMatch, ➡️ прямой контакт, 🔍 ручной подбор. В «Сделку» и «Ручной подбор» добавлены детали заявки: цель, сроки, форматы, требования к контенту и понравившиеся блогеры (пустые поля пропускаются). Они отправляются через `after()` уже после ответа пользователю: если Telegram недоступен, ответ API от этого не ломается и не замедляется.

## Проверка (`npm run smoke`)

`scripts/smoke.ts` гоняет запущенный сайт по чек-листу приёмки и проверяет:

- 5 заявок с разными нишами и бюджетами: в каждой ≥ 3 блогера, ответ быстрее 2 с;
- в ответах API нет `contact`;
- валидация, honeypot, лимит (11-я заявка → 429);
- сценарии «1–2 блогера», пустая подборка, ручной подбор;
- оба варианта связи, контакт блогера не из подборки → 404;
- приём 6 событий и отбрасывание лишних;
- все 4 представления.

В конце скрипт удаляет свои данные (`session_id = smoke-…`), чтобы не искажать метрики. Нужны `SHOW_TEST_DATA=true` на сервере и `SUPABASE_*` в `.env.local`.

## Принятые решения (не описанные в ТЗ)

- **Next.js 15**, а не 14: ТЗ допускает «14+», а в ветке 14 есть известные уязвимости. Сборка на последнем патче 15.5.x.
- **`@supabase/postgrest-js` вместо полного `supabase-js`.** Используется только REST, а свежий `supabase-js` на Node 20 падает в скриптах из-за отсутствия нативного WebSocket (нужен для realtime, который нам не нужен). Storage для аватаров не задействован в коде: в `avatar_url` можно вставить публичную ссылку на файл из Supabase Storage.
- **Лимит 10 заявок/час с IP — in-memory** (`lib/rateLimit.ts`). На Vercel у каждого инстанса своя память, поэтому лимит приблизительный; для защиты от случайного спама в MVP этого достаточно. Есть ещё honeypot. Мягкие лимиты стоят и на `/api/contact` (60/ч) и `/api/events` (300/ч).
- **`{контакт}` в подтверждениях** («напишем вам в …») берётся из localStorage устройства, с которого отправлена форма: API по ТЗ не отдаёт контакт ни в одном ответе. На другом устройстве показывается «указанный вами контакт».
- **Порядок карточек в модалке** случайный, фиксируется на `session_id` в localStorage и пишется в `deal_choice.order`. Обе карточки одинаковой высоты, с одинаковыми тёмными кнопками «Выбрать», без «Рекомендуем».
- **«Подробнее»** раскрывает полную карточку на месте, без отдельной страницы `/creator/[id]`. Событие `card_opened` отправляется при раскрытии.
- **Пустая подборка**: вместо «Нашли 0 блогеров» показывается пустое состояние.
- **`deadline`** хранится как `week | two_weeks | month | ГГГГ-ММ-ДД`.
- **«Минимальная цена»**: если клиент выбрал форматы, которые блогер не делает, блогер не проходит фильтр бюджета.
- **Ничья по баллам**: после доли Алматы сортировка идёт по `handle` — для стабильного порядка.
- **«Активен»** (дата последней публикации) показывается в полной карточке, только если `last_post_at` заполнен.
- **События**: `results_viewed` и `time_to_results` отправляются один раз на заявку с устройства (повторные открытия не дублируются). События идут батчем через `fetch keepalive`, при уходе со страницы — через `sendBeacon`. Сервер принимает только 6 разрешённых имён и проверяет `props` по схеме.
- **Цвет**: фирменный коралл `#FF5A4E` используется для декора, а для кнопок и текста — более тёмный `#D6342A`, чтобы белый текст проходил контраст WCAG AA (≥ 4.5:1).
- **Ссылка «Как это работает»** в шапке скрыта на экранах уже 400 px: на 360 px не помещается рядом с кнопкой. Блок идёт сразу под первым экраном.
- **`TEAM_CONTACT`** (`lib/copy.ru.ts`) — заглушка `@admatch_team в Telegram`. **Замените на реальный контакт перед запуском.**
- Все тексты интерфейса лежат в `lib/copy.ru.ts`. Для казахской версии нужно создать `copy.kk.ts` с той же структурой.
